# APINexus — Project-Scoped Copilot Context

## Project Overview
Centralized Scalar UI aggregating multiple OpenAPI documents — both internal services
and external/third-party APIs — behind a single authenticated interface. Which APIs a
signed-in user can see is controlled per-user by role.

## Root Namespace
`APINexus`

## API Source Abstraction
- `IApiSourceProvider` (Services/) — returns `IReadOnlyList<ApiSourceDescriptor>`.
  **Synchronous by design**: Scalar's dynamic `MapScalarApiReference((options, httpContext) => ...)`
  callback is sync, and the current provider reads in-memory config. A future DB/remote-backed
  provider should self-refresh via a background cache and expose a non-blocking sync read —
  do not make this interface `async`.
- `ConfigurationApiSourceProvider` (Services/ApiSourceProviders/) — current (only) implementation,
  bound from the `ApiSources` config section via `ApiSourcesOptions` (Configuration/).
- `ApiSourceDescriptor` (Models/) — `Id`, `Title`, `SpecUrl`, `RequiredRoles`. Empty
  `RequiredRoles` means visible to every authenticated user.

### ApiSources configuration schema
```jsonc
"ApiSources": {
  "Sources": [
    { "Id": "clientapi", "Title": "Client API (local)", "SpecUrl": "https://.../openapi/v1.json", "Roles": [] },
    { "Id": "billing",   "Title": "Billing API (restricted)", "SpecUrl": "https://billing.internal/openapi.json", "Roles": [ "Admin" ] }
  ]
}
```
`Id` becomes the Scalar document name (used in `/scalar/{id}` URLs) — keep lowercase.

## Authentication & Authorization
- Cookie authentication (`CookieAuthenticationDefaults.AuthenticationScheme`), login path
  `/login.html` (static page in `wwwroot/`).
- Users and roles are config-based for v1: `UsersOptions` (Configuration/), section `Users`.
  **Never store plaintext passwords** — hashes are produced with `PasswordHasher<string>`
  (`Microsoft.AspNetCore.Identity`, part of the ASP.NET Core shared framework — no extra
  package needed). `ConfigurationUserAuthenticator` (Services/) verifies against the hash.
- Dev-only seed accounts live in `appsettings.Development.json` only — `appsettings.json`
  ships with an empty `Users.Accounts` list. Do not commit real credentials to either file.
- `AuthController` (Controllers/): `POST /api/auth/login` (anonymous), `POST /api/auth/logout`,
  `GET /api/auth/me`.
- `/scalar` is gated with `.RequireAuthorization()`; unauthenticated browser requests are
  redirected to `/login.html`, API (`/api/**`) requests get a plain 401 instead of a redirect
  (see `OnRedirectToLogin` override in Program.cs).
- Seeded with two dev accounts (admin/ChangeMe123! → Admin role, dev/ChangeMe123! → Developer role) 

## Scalar Wiring
- `ScalarDocumentComposer` (Scalar/) — called from the dynamic `MapScalarApiReference` overload.
  Reads the current user's `ClaimTypes.Role` claims, calls `AddDocument` only for API sources
  the user is authorized for (unauthorized sources are **fully hidden**, not just read-only).
- `WithProxy(...)` is **opt-in** via the `Scalar:ProxyUrl` config setting (`ScalarProxyOptions`),
  so "Test Request" calls against externally-hosted APIs don't fail on browser CORS. Leave it
  unset to disable (default for the base `appsettings.json`); `appsettings.Development.json`
  enables it against Scalar's hosted proxy (`https://proxy.scalar.com`) for local convenience.
  Swap for a self-hosted proxy (see the OSS Go proxy in the Scalar repo) before pointing this
  at sensitive internal APIs, or leave disabled entirely if all sources are same-origin.

## Explicitly Out of Scope (v1)
- Request collection import (Postman/Insomnia/etc.)
- External IdP / OAuth2 / Windows authentication
- DB-backed or dynamically-editable user/role store
- Per-endpoint custom code samples (see ClientAPI's `OpenApi/` folder for that pattern if needed later)

## Registered Services (Program.cs)
- `IApiSourceProvider` → `ConfigurationApiSourceProvider` (Scoped)
- `IUserAuthenticator` → `ConfigurationUserAuthenticator` (Scoped)
